## 三、硬性覆盖项 B：自定义输出目录名与安全规则——结论与措辞级草案

### 3.1 结论（采纳管理侧指定口径①，并补三条安全细化）

**① 仅默认目录保留"清空旧 `*.png`"；自定义输出目录不自动清理，只覆盖同名产物。** 在此基础上补：

1. **判定口径**：以"实际输出路径是否等于程序根下 `已排版`"为准（不论是否经选择器选中它）。GUI 与 CLI 共用同一个规则函数，保证两入口同语义。
2. **提示义务**：自定义目录运行时，启动前/结束时在日志与状态行给出不打断的提示：「本目录不会自动清理：已存在同名产物 N 个（将覆盖）；检测到本工具旧页 N 张（不删除）」。默认目录照旧「先清空后写入」，同样记录清理条数。
3. **创建规则**：自定义输出目录不存在时只创建最后一级（父目录必须存在）；相对路径按程序根解析。**CLI 现状为多级自动创建（parents=True）**——本批保持 CLI 现状（已过验收的路径不动），差异写入使用说明；如需两入口完全统一，另行拍板（§九-7）。

**为什么选①而不是"统一只清理本工具命名模式（②）"**：①对默认目录做到**零语义变化**（"默认不退化"最彻底，旧行为连"清除非工具命名 PNG"这一历史细节都保持）；对自定义目录给出最朴素的承诺——"工具只写不删，你的目录你做主"。②虽然能顺带治"自定义目录旧页残留"，但会改动默认目录的既有边界（非工具命名 PNG 不再被删），与"默认完全不变"的总原则冲突，且需要额外解释。自定义目录的"旧页残留"风险改由 §3.1-2 的提示义务显式暴露给操作者（不自动处理、不沉默）。

### 3.2 现场证据（误删风险，两轮评审各复现一次）
