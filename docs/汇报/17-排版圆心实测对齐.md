- 角色：开发工程师 · 2026-10-06（第六回，修配变更 `layout-center`）
- 变更链路：实现 `03923b0` → 文档 `221d8ee` → 归档 `30670e2` → 本文件
- 一句话结论：**使用者现场「还是有点偏差」已定位并修掉**——根因不在半径（上一次已修），而在**绘制用的圆心**：图案模板上 `detect_slots` 的检测圆心被花纹抬高 0.1~15.9px（11 槽位中 6 个 +10.6~+15.9px）。本次新增「圆盘圆心实测」（自圆盘外向内取首个非白边界点 → 质心 + 截尾圆拟合）作为**徽章与定位点的共同绘制中心**；现场模板徽章圆心与模板圆盘圆心距离 **10.11px → 0.95px**，同排两槽的 y 差 **14.52px → 0.10px**，行间距收敛为 442.5±0.5px；入库旧模板逐像素不变（golden `rgb>8=1141` 照旧）；打包版已重建、现场已恢复复跑（与源码版逐字节一致）。

## ① 任务与范围

- 使用者反馈（原话）：「**最好能完全对齐，似乎还是有偏差**」。
- 根因诊断（逐像素实测，见 ③）：
  1. 上一次 `layout-fit` 只修了**半径**（检测半径被花色干扰为 412–428px，实测圆盘恒 r≈411.7，徽章外缘已贴合）；
  2. **圆心没修**：徽章画的仍是 `detect_slots` 的检测圆心，而它在图案模板上被抬高——11 个槽位实测修正 +0.11~+15.86px（y 方向，6 个 >10px）；
  3. 于是输出页里徽章整体比圆盘高 12~16px：同一排的两个槽位（#4/#5）y 差 14.5px、行间距忽大忽小（1.0 / 438.9 / 441.2 / **14.5** / 429.4 / 445.5 / **11.3** / 431.4 / 442.3 / **10.9**），观感就是「没对齐」。
- 机制：`detect_slots` 的包围盒来自前景连通域，图案模板上花纹与圆盘粘连（上一次已证：检测半径 412→428），`_fit_circle_cross` 的「包围盒中心十字弦」随之外扩、中心被抬高。**检测算法冻结不改**，本次只在「绘制中心」层做实测校正。
- 本次范围：新变更 `layout-center` —— `badge-layout` 新增一条需求「圆盘圆心实测（绘制中心校正）」；实现 + 用例 + 打包重建 + 现场备份/恢复/复跑 + 文档同步。刻意**不改**「页面合成与缩放」需求文本，避免他线 `flexible-io` 的同一块再次过期（实测归档后 `flexible-io` 仍全绿）。
- 非目标（保持）：不改 `detect_slots`；不改半径语义与定位点几何参数（8.5 / 17 / 24px）；不新增 GUI / CLI 选项；不动目录契约与输出命名。
